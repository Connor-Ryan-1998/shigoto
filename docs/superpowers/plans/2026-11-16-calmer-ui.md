# Calmer warm-sage UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stock DaisyUI look with a calm, warm-sage identity across the staff and portal shells and shared components, without changing behaviour.

**Architecture:** Two custom DaisyUI 5 themes in `app.css` carry colour, radius and font, so every screen (including ~30 hand-copied surfaces) softens through tokens. The two layouts and the shared components in `web/src/lib/components/` drop hard borders and gain icons from a new dependency-free `Icon.svelte`. Nav icons are declared in module manifests.

**Tech Stack:** Svelte 5 / SvelteKit, Tailwind 4, DaisyUI 5, Vitest + Testing Library, Playwright, `@fontsource-variable/source-sans-3`.

**Spec:** `docs/superpowers/specs/2026-11-16-calmer-ui-design.md`

## Global Constraints

- No behaviour change: links, permissions, module gating, focus, dialog/drawer dismissal, skip links, `aria-current`, print layout all retained.
- Body and muted text ≥ 4.5:1; primary text on primary ≥ 4.5:1; in both themes.
- Status never by colour alone; badges keep text.
- No glassmorphism/blur/translucent surfaces over tables.
- No remote fonts or CDN assets. Only new dependency: `@fontsource-variable/source-sans-3`.
- No new component kit or icon library.
- Theme names: `shigoto-light` (default), `shigoto-dark` (prefers-dark).
- Visible label "Logout" becomes "Sign out" in both shells.
- Use semantic DaisyUI tokens (`base-*`, `primary`, …), never hard-coded per-screen colours.
- Run Taskfile checks sequentially via `uv run --locked task …` from the repo's app directory; never concurrently.

## Review Focus

- **Muted text in dark mode** (`text-base-content/70` on base-100/base-200): must stay ≥ 4.5:1 → contrast test in Task 1.
- **"Auto" theme with no `data-theme`**: OS dark mode must get `shigoto-dark`, not a stock theme → app.css declaration test in Task 1.
- **A nav item with no `icon`** (future module): renders the label with no empty/broken SVG → test in Task 3.
- **375px viewport**: top bar wraps, menu button reachable, no horizontal page scroll → manual check in Task 5 plus existing `e2e/smoke.spec.ts`.
- **Rental report print preview**: shell chrome still hidden in print → manual check in Task 5.

```ts
import { readFileSync } from 'node:fs';
import { describe, expect, it } from 'vitest';
import { theme } from './theme.svelte';

const css = readFileSync(new URL('../app.css', import.meta.url), 'utf8');

// Parse `@plugin "daisyui/theme" { name: "<name>"; --color-x: #hex; ... }` blocks.
function themeTokens(name: string): Record<string, string> { /* builder: regex the block whose name matches, collect --color-* hex values */ }
function contrast(fg: string, bg: string, alpha = 1): number { /* WCAG 2.x relative-luminance ratio; blend fg over bg at alpha first */ }

describe('warm-sage themes', () => {
	it('declares light as default and dark for prefers-dark', () => {
		expect(css).toMatch(/name:\s*"shigoto-light";[\s\S]*?default:\s*true/);
		expect(css).toMatch(/name:\s*"shigoto-dark";[\s\S]*?prefersdark:\s*true/);
		expect(css).not.toMatch(/corporate|business/);
	});
	it.each(['shigoto-light', 'shigoto-dark'])('%s keeps readable text', (name) => {
		const t = themeTokens(name);
		for (const bg of [t['--color-base-100'], t['--color-base-200']]) {
			expect(contrast(t['--color-base-content'], bg)).toBeGreaterThanOrEqual(4.5);
			expect(contrast(t['--color-base-content'], bg, 0.7)).toBeGreaterThanOrEqual(4.5);
		}
		expect(contrast(t['--color-primary-content'], t['--color-primary'])).toBeGreaterThanOrEqual(4.5);
		expect(contrast(t['--color-primary'], t['--color-base-100'])).toBeGreaterThanOrEqual(4.5);
		expect(contrast(t['--color-warning-content'], t['--color-warning'])).toBeGreaterThanOrEqual(4.5);
		expect(contrast(t['--color-error-content'], t['--color-error'])).toBeGreaterThanOrEqual(4.5);
	});
	it('applies the shigoto theme names', () => {
		theme.current = 'light'; theme.apply();
		expect(document.documentElement.dataset.theme).toBe('shigoto-light');
		theme.current = 'dark'; theme.apply();
		expect(document.documentElement.dataset.theme).toBe('shigoto-dark');
		theme.current = 'system'; theme.apply();
		expect(document.documentElement.hasAttribute('data-theme')).toBe(false);
	});
});
```

All colour tokens in app.css must be written as 6-digit hex so this parser works.
